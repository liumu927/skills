# 考核表填写

三种模式，共用同一套"编辑 docx XML → 保留原格式 → Word 渲染验收 → 回写"的流程：

| 模式 | 场景 | 详见 |
|---|---|---|
| **A 季度汇总** | 由当季 3 个月度表汇总出季度考核表 | 下文 |
| **B 月度细化** | 按工作日志把月考核登记表的完成情况拆条写细 | `references/log-to-monthly.md` |
| **C 下月计划** | 复制模板生成下月空白计划表，只填计划任务 | 下文 |

判断依据：目标是"季度考核表/季度考核登记表"→ 模式 A；目标是"月考核登记表/月度工作计划表"且给了日志或月报 → 模式 B；目标是**下个月**的"计划表"、要的是空白待填 → 模式 C。

# 模式 A：季度考核表填写

把 7/8/9（或 1/2/3…）三个月的月度工作计划表实际完成情况，对应汇总进季度考核表。全程直接编辑 docx XML 保留原表格式，经 Word 渲染 + 视觉验收后回写原路径。

## 需要的输入

1. **季度考核表**（目标文件，通常在共享盘，如 `\\192.168.2.99\taichi\…\优化组工程师-某某-2026年第X季度考核表.docx`）。表内已预填"计划任务"列，需要填的是：各计划行的"完成情况"列 + 工作作风情况 + 改革创新情况 + 总体评价意见。
2. **当季三个月度工作计划表**（月考核登记表，含每项"计划任务"和实际"完成情况"）。

用户可能只给部分路径。先检查文件是否可访问（Git Bash 下 UNC 路径写 `//host/share/…`）；缺哪个就向用户要哪个，不要自己猜路径或找同名替代文件。检查共享目录里是否有 `~$` 开头的临时文件——有则说明该文件正被人用 Word 打开着，回写前要提醒用户关闭。

## 工作流

### Step 1 备份并复制到本地工作目录

```bash
mkdir -p work && cp "<季度表UNC路径>" work/季度考核表.docx && cp "<各月表>" work/7月.docx …
cp work/季度考核表.docx work/原表备份.docx   # 原表备份，回写失败时可恢复
```

### Step 2 提取所有文档内容

```bash
python "<skill目录>/scripts/extract_tables.py" work/*.docx
```

输出每个文档的行列文本。月度表关注"计划任务 || 完成情况"两列；季度表记下：预填的计划任务有哪几行、哪些单元格待填（完成情况列空段、工作作风/改革创新/总体评价三栏）。

### Step 3 参考同目录同事已填的季度表（代替用户上传截图）

用户不会传格式截图——格式样板直接从共享目录里找**同事已填好的季度考核表**（文件更新日期接近当季、且完成情况列非空的）。复制一份提取其完成情况列：

- 总-分句式（如"完成，包括：”+ "(1)…(2)…"）
- 各栏（工作作风/改革创新/总体评价四点）的句式长度和语气

后续写作仿照该同事的措辞风格，但事迹必须换成目标用户本人的。

### Step 4 建立月度→季度的对应关系

列出季度表每个计划行，把三个月的实际工作分配进去。硬性原则：

- **不瞎编**：完成情况里每一条都必须能在月度表里找到出处；没做的不写。
- **不照抄**：对月报原文归纳提炼（把同一件事跨月的推进合并成一条完整叙述），不逐字复制。
- **不遗漏**：三个月月报中所有实际完成事项都要有着落。
- **计划外归集**：月度实际做了、但季度计划没覆盖的工作，写进"其他计划外任务"行（含用户点名要加的条目）。注意：某项工作虽然出现在某月的"计划外"里、但季度计划中有对应条目的（如 DeerFlow 调研），应归入该计划行而非计划外，避免重复。
- **如实标注未开展**：季度计划有、但三个月都没做的行，写"本季度未开展相关工作。"，不编造、不回避。
- **状态如实**：月报里"推进中/持续进行"的工作，汇总时保留该状态（如"后续仍在持续深化"）。

### Step 5 填写完成情况列（总-分结构）

每个计划行的完成情况：总述一句（"完成，包括："/"完成。"）+ 分条 "(1)(2)(3)…"，每条一句话概括该子计划实际做成了什么。参照 `references/ooxml-numbering.md` 的编号规则——**这是最容易踩坑的部分**：总述和分条各自需要新建独立 numId，绝不能复用表内已有 numId，否则会打乱计划任务列的连续编号或造成跨行连号。

run 字体与原表正文一致（本表为楷体_GB2312，sz=24 即小四），从原表现有 run 的 rPr 原样复制。

### Step 6 填写工作作风、改革创新、总体评价

- **工作作风情况**：一句话通用作风描述（认真负责、按时出勤、主动同步进度、严保交付质量），仿同事表句式。
- **改革创新情况**：一句话列举 2~4 项有新意的技术实践（新技术引入、架构重构、提效工具），从完成情况里挑。
- **总体评价意见**：在"取得成果：/成长进步：/亮点工作：/不足之处："四段冒号后各追加**一句话**（30~45 字，单句收尾）：
  - 取得成果：本季度完成了什么、保障了什么；
  - 成长进步：能力从哪拓展到哪；
  - 亮点工作：最有代表性的一两项成果（带量化数字更佳）；
  - 不足之处：如实但有分寸——从月报中"持续进行/仍存在问题"的项提炼，不写已完成的事。

### Step 7 打包 → 渲染 → 视觉验收 → 回写

```bash
python "<skill目录>/scripts/pack_docx.py" work/unpack work/output.docx
python "<skill目录>/scripts/render_check.py" work/output.docx work/page   # 依赖 Word COM + pymupdf
```

把生成的 PNG 交给 judge 子代理验收（检查：编号正确、格式一致、无溢出截断、表格其余部分未回退）。通过后回写并校验：

```bash
cp work/output.docx "<季度表UNC路径>"
md5sum work/output.docx "<季度表UNC路径>"
```

本机 Git Bash 可能没有 `md5sum`（`command not found`），用 python 兜底：

```bash
python -c "import hashlib,sys;[print(hashlib.md5(open(p,'rb').read()).hexdigest(),p) for p in sys.argv[1:]]" work/output.docx "<目标路径>"
```

最终回复引用一次输出文件（`::zcode-file-citation{path=… purpose="output"}`），附对应关系简表与特殊处理说明（未开展的行、计划外归集、编号修复等）。

# 模式 B：月考核登记表按日志细化

目标是**月考核登记表**（`…YYYY.MM月份工作计划表.docx`，表头写"月考核登记表"），业主给了工作日志（Obsidian「待办导出」md、工作区工作总结、周报……），要把"完成情况"列从笼统话改成逐条明细。**完整规则见 `references/log-to-monthly.md`，先读再动手**，要点：

1. **解析日志**：`python scripts/parse_todo_log.py <待办导出.md> todo.json` → 按日期分组、带勾选状态与子项层级的树。手工通读一遍，标出每条属于哪个计划行。
2. **归类**：一行一事，**别把两件事并成一句**（典型坑：把"资产管理信息可视化开发"和"钉钉OA流程定制化开发"当作一件；资产 OA 审批只是前者的实现手段，须分别表述）。日志里有、计划行没有的活 → 归入"其他计划外任务"。
3. **口径**：以考核截止日期为准，业主会补完的未勾选条目照样写入，但措辞留余地（"已开展/已定位待修复"）。未做过的不编。
4. **写法**：总述一句（可含量化范围）+ `(1)(2)(3)` 分条，每条 40~70 字，数字优先。
5. **排版关键差异**：月表**没有** Word 自动编号，`(1)` 直接写进文字、每条独立段落，**绝不新建 numId**（月表的 numId 只给计划任务列的 1.~N. 用）；从原单元格首段复制 run 格式（微软雅黑 sz=18）；条目段落加悬挂缩进 `left=170 hanging=170`。
6. **对齐**：表格样式通常是 `jc=both`（两端对齐），窄栏里一旦出现 `→stdout→WebSocket`、`O(n²)` 这类不可断的拉丁串，Word 会把中文字距拉开成"走 通 YAML → 子 进 程"。两步治：先去掉中英文之间的空格（`139例`、`OA表单`），仍不干净就给这些单元格 `align=left`（`fill_cells.py` 支持），宁可右边缘参差。
7. **不许动**：计划任务列、评价意见列的 Wingdings 2 勾选、考核内容/评估要点/评分列、签字栏及**浮动签名图片**（锚定在签名段，行高变化会跟着走，删改签名段就丢签名）。
8. 页数会变多（本例 2 页 → 3 页，末页只放考核结论区与签字行属正常），渲染确认后回写。

# 模式 C：生成下月计划表

业主给一份本月（已填）的表 + 任务清单/上月遗留，要产出**下个月的空白计划表**：只填"计划任务"，完成情况空着。做法就是复制模板 + 改内容。

```bash
cp "<本月表>" work/base.docx          # 以业主手上那份为模板，别另找模板
cd work && mkdir -p unpack && python -c "import zipfile;zipfile.ZipFile('base.docx').extractall('unpack')"
python scripts/new_month_plan.py unpack plan.json
python scripts/pack_docx.py unpack out.docx
```

`plan.json`：

```json
{"month": "2026.11", "date": "", "clear_eval": true, "clear_signature": true,
 "keep_eval_block": true,
 "tasks": ["k4项目：……。", "信息化工作：……。", "其他计划外任务。"]}
```

脚本自动做：改考核月份 → 按 tasks 数量增删计划行（保留 `numId` 自动编号 1.~N.）→ 清空完成情况 → 评价意见 ☑ 全部退回 □ → 清空评估要点（上月评语不能带到下月）→ 去掉签名图片、清空日期 → 考核结论块整体不跨页。行定位靠表头文本，不写死行号。

**计划任务从哪来**：① 任务清单里还没做的（Obsidian 待办顶部的无日期清单就是这类）；② 上月遗留（"待修复/尚待打通/计划下一周期推进"的项，包括模式 B 里写在最后一条的收尾项）；③ 上月计划行里仍在推进的（改成本月要推进的具体动作）。**别只信任务清单**——工作区历史会话里常留着"发现了但没修"的清单，扫一遍拿到的才是硬素材（做法见 `references/log-to-monthly.md` 的"工作区会话里还没做完的活"）。每条一行、以句号结尾，写法照抄本表既有风格（"信息化工作：XXX。"），不写"完成情况"式的结果描述。

**写具体，不写代号**：这张表是给人看的，`P0`/`P1`、`E2E`、`VI`、`Schema`、`CI` 这类内部缩写和优先级编号一律展开成中文——"浏览器端端到端测试"、"视觉规范"、"表单定义"、"持续集成"、"历史任务被整目录删除导致日志丢失"。优先级不用写进计划表，靠行序体现即可。

**排版三查**（都靠渲染看结果，只看 XML 发现不了）：

- **行高**：克隆的"其他计划外任务"行常带 `trHeight=1525`（上月内容多撑起来的），复制到下月会留一大段空白把表撑高。脚本已统一取计划区间最小行高；手工加过行就得自己压回去。
- **考核块不跨页**：任务一多，"考核内容"表头会被留在第 1 页页脚、5 行评语跑到第 2 页——很难看。脚本默认给考核块加 `cantSplit` + `keepNext`（`keep_eval_block: false` 可关），让表头、评语、签字整体落在同一页。注意 `keepNext` 必须下沉到单元格里的 `w:p/w:pPr`（段落嵌在 `w:tc` 内，用 `tr.findall('w:p')` 是找不到的，得用 `iter`）。
- **页数预算**：该列宽约 4.5cm，每条任务约 3 行文字。实测：**6 条 → 整表 1 页**（考核块同页）；**8 条 → 第 1 页刚好占满，考核结论区+签字整体到第 2 页**（可接受，但第 2 页不能只剩签字行）；再往上第 2 页就会先塞一两条任务行，分页变难看，宁可合并条目。

**别动**：姓名/单位/岗位/入职时间（业主自己维护）、考核内容与评分列、签字栏版式。

# 脚本

| 脚本 | 作用 |
|---|---|
| `scripts/extract_tables.py` | 提取 docx 表格与段落文本，建立月度↔季度对应关系 |
| `scripts/fill_cells.py` | **按 JSON 重写指定单元格的段落**（保留 tcPr/字体；`(` 开头自动悬挂缩进），A/B 模式共用 |
| `scripts/parse_todo_log.py` | 解析 Obsidian「待办导出」md → 按日期分组的任务树 JSON |
| `scripts/new_month_plan.py` | **复制模板生成下月空白计划表**（改月份、换计划任务、清完成情况/评语/签名） |
| `scripts/pack_docx.py` | 解包目录重新打包为 docx（Windows 无 zip 命令时用） |
| `scripts/render_check.py` | Word COM 渲染 PDF → 逐页 PNG，供视觉验收 |

`fill_cells.py` 的输入格式（rw 均为 0 基，指 `w:tbl` 的行列）：

```json
{"cells": [{"table": 0, "row": 5, "col": 2, "align": "left",
            "paras": ["总述一句，包括：", "(1) 第一条", "(2) 第二条"]}]}
```

## 交付底线

- 模式 A/B：修改只发生在待填单元格内；表格其余部分（计划任务列、考核结果勾选、评估要点、签字栏、签名图片）一字不动。用单元格级哈希对比自证（见 `references/log-to-monthly.md` 验收清单）。
- 模式 C 是**新建文件**，不改动原月份的表；新文件名按 `…YYYY.MM月份工作计划表.docx`，与原件同目录。
- 回写/落盘前必须确认目标文件没被 Word 锁定（无 `~$` 临时文件）。
- 回写后必须 MD5 校验一致；模式 A/B 回写前先把原文件复制一份 `.bak` 备份。
- 任何一步验收不过都不回写。
