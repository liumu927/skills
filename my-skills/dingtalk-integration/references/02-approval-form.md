# 审批表单连接器绑定

适用：审批表单里要动态取 AI 表格的数据——要么作为单选项的选项来源，要么选定某个值后回显表里的其他字段。

前置：`01-connector-oauth2.md` 的基建已跑通（自建应用 + 凭证 + 连接器动作已发布）。

## 两种用途

### 用途一：动态下拉选项

1. 表单里先放好单选控件。
2. 绑定连接器：触发条件优先"**新建表单加载时**"（打开表单即加载选项）；没有该选项时用"控件值发生变化时"+ 前置控件。
3. 执行动作入参：baseId / 表 ID / operatorId / maxResults=100。
4. 出参映射两行，**缺一不可且必须等长**：
   - `控件.选项列表.值列表` ← 字段值数组（如项目名称）
   - `控件.选项列表.ID列表` ← 记录 ID 数组
5. 发布审批模板，发起实测。

### 用途二：选值后回显字段

1. 表单里先放好用于回显的**文本控件**——控件必须先存在，出参映射才选得到（配映射后再加控件会找不到）。
2. 触发条件选"**控件值发生变化时**"+ 前置控件=查询依据控件。不要用"新建表单加载时"：此时依据控件还没值，条件为空。
3. 动作入参的条件筛选：
   - 字段 = 表内列名（如 `项目名称`）
   - 操作符 = 等于类
   - 值 = 引用表单控件（调试期用固定值，绑模板时换动态引用）
4. 出参映射取数组第一项：
   - `回显文本控件` ← `records[0].fields.项目负责人`
   - `负责人unionId(回显)` ← `records[0].fields.负责人unionId`
5. 把查询依据控件设为**必填**，保证提交时条件值非空。
6. 回显控件对发起人设为**只读**（防手改 unionId 把审批人改飞）。
7. 发布模板。

## 设计约束（实测确认）

- 表单级连接器绑定**一次触发只发一个请求**，不能拿到结果后再链式调第二次。需要二次转换（如 unionId→userId）时，把中间值落到文本控件，由流程节点再做第二次调用（见 `03-approval-process.md`）。
- **联系人控件不能用 unionId 回填**，它按 userId 定位人；多维表里存的是 unionId。表单层用文本控件回显，别在联系人控件上反复尝试。
- 出参 `records` 是数组，文本控件是标量，必须取下标 `[0]`。
- 不要用官方 AI 表格连接器做字段回填：它的出参只暴露记录 ID/是否更多/游标，字段值无法声明。自建 HTTP 连接器导入真实 JSON 声明出参。

## 验证清单

- [ ] 新建表单时下拉有选项；表内增删记录后选项自动变化
- [ ] 选项目 A → 回显 A 的负责人；改选 B → 回显跟随变化
- [ ] 提交后审批节点落到正确的人（若配置了流程路由）
- [ ] 换一个项目再发起，结果跟随
- [ ] 项目名重复时确认取的是哪一条（重复名会导致下拉出现两个同名项，回显/派单可能取错）

## 踩坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 回填报"值列表、ID 列表长度应该一致" | 只映射了值列表 | 两行都映射 |
| 下拉选项为空但无报错 | 映射没配/没发布/触发条件未满足 | 查两行映射、模板发布、"新建表单加载时" |
| 选完控件仍空白 | 没取数组第一项；或条件三要素不全；或表里无匹配记录 | 依次核对 |
| 配映射时目标下拉找不到文本控件 | 控件是配映射之后才加的 | 先加控件保存，再配映射 |
| 回显内容与预期不符 | 项目名多空格/全半角/年份后缀不一致 | 逐字符核对表内值与表单提交值 |
| 初始加载就报错/查无结果 | 触发条件用了"新建表单加载时"但依据控件为空 | 改"控件值发生变化时"+ 必填 |
| 改了连接器行为没变化 | 发布链断了 | 动作发布 → 连接器发布 → 模板发布 |

## 复用

- 换表/换字段：改 baseId/表 ID、重新导入出参 json、重配映射，三处同步。
- 换条件维度（按编号查负责人、按部门查主管）：改条件字段 + 出参字段 + 映射，架构不动。
- 一个项目查多个字段：按需加文本控件，每个都从 `records[0]` 取。
