# S2 多维表 → 审批表单与流程

适用：审批表单要动态取 AI 表格的数据——作为单选项的选项来源、选定后回显表里字段、或让第一个审批节点自动派给表里的负责人。

前置：[01-app-and-connector-auth.md](01-app-and-connector-auth.md) 的基建已跑通（自建应用 + 凭证 + 连接器动作已发布）。

## 两种用途

### 用途一：动态下拉选项

1. 表单里先放好单选控件。
2. 绑定连接器：触发条件优先"**新建表单加载时**"（打开表单即加载选项）；没有该选项时用"控件值发生变化时"+ 前置控件。
3. 执行动作入参：baseId / 表 ID / operatorId / maxResults=100。
4. 出参映射两行，**缺一不可且必须等长**：
   - `控件.选项列表.值列表` ← 字段值数组（如项目名称）
   - `控件.选项列表.ID列表` ← 记录 ID 数组
5. 发布审批模板，发起实测。

### 用途二：选值后回显字段

1. 表单里先放好用于回显的**文本控件**——控件必须先存在，出参映射才选得到（配映射后再加控件会找不到）。
2. 触发条件选"**控件值发生变化时**"+ 前置控件=查询依据控件。不要用"新建表单加载时"：此时依据控件还没值，条件为空。
3. 动作入参的条件筛选：
   - 字段 = 表内列名（如 `项目名称`）
   - 操作符 = 等于类
   - 值 = 引用表单控件（调试期用固定值，绑模板时换动态引用）
4. 出参映射取数组第一项：
   - `回显文本控件` ← `records[0].fields.项目负责人`
   - `负责人unionId(回显)` ← `records[0].fields.负责人unionId`
5. 把查询依据控件设为**必填**，保证提交时条件值非空。
6. 回显控件对发起人设为**只读**（防手改 unionId 把审批人改飞）。
7. 发布模板。

## 流程派单：两段式（表里的负责人 → 审批节点）

前置：用途二已把负责人姓名和 unionId 回显到表单文本控件。

```
表单层（一次请求）
  选定项目 → 连接器按项目名查表 → 回显负责人姓名 + 负责人unionId 到两个文本控件
        ↓ unionId 落到控件里（参数桥）
流程层（流程运行时再发一次请求）
  节点负责人来源=连接器 → 系统自带「通讯录」连接器
        ↓ 动作「根据unionid获取用户userid」
        ↓ 入参 unionId ← 表单控件「负责人unionId(回显)」
        ↓ 出参 userid → 该节点审批人
```

为什么必须两段：

- 审批节点按 **userId** 定位人，多维表人员列里存的是 **unionId**。
- 表单级连接器不能链式调用，拿到 unionId 后没法在表单里再调一次换 userId。
- 流程级节点只能引用表单控件值或固定值，拿不到表单级连接器的运行时出参。

所以 unionId 必须落到文本控件——这是第二次调用的**参数桥**，不只给人看。

### 配置步骤

1. 按用途二配好两个文本控件（负责人姓名、负责人 unionId）。
2. OA 审批后台 → 编辑模板 → 流程设计 → 目标节点 → 审批人。
3. 负责人来源选"**连接器**" → 选**系统自带「通讯录」**（平台托管、免鉴权，不要自建）。
4. 动作「**根据unionid获取用户userid**」；入参 unionId = 引用表单控件 `负责人unionId(回显)`。
5. 出参 userid 自动成为节点负责人。
6. 两个回显控件对发起人设为**只读**；发布模板。

## 人员标识：表里的和表单/节点要的不是同一套 ID

这是 S2 最容易踩死的地方。四条事实：

1. 多维表**人员列**存的是 unionId（直连 API 写入形态 `[{"unionId":"..."}]`），**人员列里放不进 userId**。
2. 表单**联系人控件**按 userId 定位人，提交后控件值是 **userId 数组**。
3. 表单级绑定**一次触发只发一个请求**，不能在表单里再调一次转换。
4. 审批节点要 userId。

于是"表里存人、表单里用人"必然缺一次转换。三种解法，按场景选：

| 解法 | 做法 | 优点 | 代价 | 何时选 |
|---|---|---|---|---|
| **A. 表里加 userId 文本列**（推荐） | 用连接流/AI 表格自动化把 unionId→userId 翻译好写进表的**文本列**（见 [04b](04b-aitable-automation.md)），表单文本控件直接回显 userId | 表单侧零转换；流程节点直接用；转换成本一次性 | 表要加一列，且人员变动要重跑翻译 | 人相对稳定、表单要频繁派单 |
| **B. 两段式（不改表）** | 表里只有 unionId → 文本控件回显 unionId → 流程节点用通讯录连接器转换 | 不动表结构 | 每次流转都多一次连接器调用 | 表结构不能动、或临时验证 |
| **C. 连接流实时回写** | 表内事件/审批事件触发连接流，单条查通讯录把 userId 写回该行 | 实时，无需定时批处理 | 要配事件触发与判重；调用次数按条计 | 表由外部系统维护、人要频繁变 |

**关键区分**：如果只是"发起人在表单里**手选**联系人"（不是从表里带出人），那控件值天然就是 userId，**不需要任何转换**——直接把 userId 数组写回表时才需要 userId→unionId（见 [04](04-connection-flow.md)）。别把两个方向搞反。

```
表 → 表单/节点：需要 unionId → userId   （解法 A/B/C）
表单 → 表：     需要 userId  → unionId  （通讯录连接器反向动作，或表里另存 userId 文本列绕开）
```

## 设计约束（实测确认）

- 表单级连接器绑定**一次触发只发一个请求**，不能拿结果再链式调第二次。需要二次转换时，把中间值落到文本控件，由流程节点做第二次调用。
- **联系人控件不能用 unionId 回填**（它按 userId 定位）。表单层用文本控件回显，别在联系人控件上反复尝试。
- 出参 `records` 是数组、文本控件是标量，必须取下标 `[0]`。
- 不要用官方 AI 表格连接器做字段回填：它只暴露记录 ID/是否更多/游标，字段值无法声明。用自建 HTTP 连接器导入真实 JSON。
- 回显是**异步**的：极速"选完就交"存在竞态，操作上要求发起人确认回显已更新再提交。

## 验证清单

- [ ] 新建表单时下拉有选项；表内增删记录后选项自动变化
- [ ] 选项目 A → 回显 A 的负责人；改选 B → 回显跟随变化
- [ ] 提交后审批节点落到正确的人；换项目再发起，节点跟随
- [ ] 人员标识链路：表里的 unionId / 文本控件里的值 / 节点最终审批人，三处能对上同一个真实的人
- [ ] 表单**手选**联系人的场景，提交后写回表的是 unionId 对象数组（不是 userId 字符串）
- [ ] 项目名重复时确认取的是哪一条（同名会导致下拉出现两个同名项，回显/派单可能取错）

## 踩坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 回填报"值列表、ID 列表长度应该一致" | 只映射了值列表 | 两行都映射 |
| 下拉选项为空但无报错 | 映射没配/没发布/触发条件未满足 | 查两行映射、模板发布、"新建表单加载时" |
| 选完控件仍空白 | 没取数组第一项；或条件三要素不全；或表里无匹配记录 | 依次核对 |
| 配映射时目标控件找不到 | 控件是配映射之后才加的 | 先加控件保存，再配映射 |
| 回显内容与预期不符 | 项目名多空格/全半角/年份后缀不一致 | 逐字符核对表内值与表单提交值 |
| 初始加载就报错/查无结果 | 触发条件用了"新建表单加载时"但依据控件为空 | 改"控件值发生变化时"+ 必填 |
| 想用联系人控件携带负责人，出参塞不进去 | 联系人控件按 userId 定位，表里是 unionId；表单级不能链式 | 改文本控件回显（解法 A/B） |
| 直接给节点 unionId，节点取不到人 | 节点要 userId | 走通讯录连接器转换，或表里存 userId 文本列 |
| 节点报"未找到审批人" | unionId 查不到 userid：离职、非本企业、表里填错 | 用"查询用户详情"核对；离职交接加"同步更新表内负责人" |
| 发起人手改 unionId 控件，审批连到别人 | 文本控件默认可编辑 | 字段权限设只读 |
| 审批人派错人 | 项目名重复，取第一条匹配 | 名称唯一性治理；或加第二字段联合过滤 |
| 提交后节点无负责人，流程不动 | 回显异步，极速提交存在竞态 | 要求确认回显已更新再提交 |
| 改了连接器行为没变化 | 发布链断了 | 动作发布 → 连接器发布 → 模板发布 |

## 复用

- 换表/换字段：改 baseId/表 ID、重新导入出参 json、重配映射，三处同步。
- 换条件维度（按编号查负责人、按部门查主管）：改条件字段 + 出参字段 + 映射，架构不动。
- 一个项目查多个字段：按需加文本控件，每个都从 `records[0]` 取。
- 一个项目多个人审批：每人一套"userId/unionId 控件 + 通讯录连接器节点"组合。
- 复制到其他模板：两段式整体照搬，连接器无需重建。
- 平台若将来支持联系人控件直接吃 unionId 或表单级链式请求，可简化为一层；现阶段按本文实施。
