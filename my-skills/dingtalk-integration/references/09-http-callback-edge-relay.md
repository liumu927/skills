# 审批通过后 HTTP 节点回调自有系统（公网边缘中转回内网）

本篇覆盖的场景在 01–05 之外：**审批结束后，连接器 HTTP 节点把数据回调写入"自有的内网业务系统"**（不是 AI 表格）。已实测实例是专利成果系统（审批通过自动入库、审批撤回自动删除），链路认知跨项目通用。

## 链路总览

```
钉钉自建应用（OA 审批模板 + 连接器 HTTP 节点）
   │  审批通过/撤回 → HTTPS 调公网域名
   │  POST https://patents.idrl.ac.cn/api/patents/upsert
   │  请求头 X-API-Token: 边缘令牌
   ▼
公网 DNS：patents.idrl.ac.cn → 腾讯云服务器公网 IP（备案接入商=腾讯云，不被合规拦截）
   ▼
腾讯云边缘服务器（无状态中转）
   nginx:443    TLS 终结（正式证书）+ 限流 + 仅回调路径白名单，其余一律 404
   relay:4330   ①校验边缘令牌 ②换发内部令牌 ③转发/回传响应 ④断链落盘队列→恢复后重放
   ▼  OpenVPN 加密隧道（VPN 账号 ACL 仅放行 NUC:4321 一个目标）
办公网 NUC（事实源，数据不出网）
   成果系统 :4321   upsert 幂等入库 / external-delete 撤销删除+留档 / 查询接口
   ▼
响应原路流式返回 → 连接器节点拿到真实成败（不加缓存不篡改）
```

各角色一句话：钉钉侧只做"配置"（审批模板上挂连接器节点）；公网服务器只做"安检口 + 转发"；真正的业务系统一直在办公网内。

## 一、为什么是这条链路（设计动机）

| 现实约束 | 结论 |
|---|---|
| 域名 ICP 备案接入商登记在腾讯云 | 服务必须落在**腾讯云大陆服务器**；放阿里云会被其合规系统拦截（接入备案不在阿里云） |
| 内网系统不能整体暴露公网 | 公网入口只保留回调 API 的几条路径；界面/登录/文件上传等一切其他功能不进公网 |
| 数据合规 | 数据库只在办公网，边缘服务器**无状态、不落业务数据**，单一事实源 |
| frp 类裸端口转发 | 等于把内网端口原样发布公网，任何客户端可直达；本方案用 OpenVPN 加密隧道 + 应用层白名单/令牌替代 |

## 二、同父域名的用法（备案/解析/证书三层关系）

`patents.idrl.ac.cn` 是父域 `idrl.ac.cn` 的子域，ICP 备案挂在整个父域上（接入商=腾讯云）：

1. **同父域新增子域不需要新增备案**——新开 `xxx.idrl.ac.cn` 沿用既有备案；变更"接入商"（比如从腾讯云换阿里云）才要动备案，且会被新服务商合规校验。
2. **拆分解析（同域名、两个方向）**：
   - 公网 DNS（腾讯云 DNSPod）：A 记录 → 腾讯云服务器公网 IP，**钉钉云端走这条**；
   - 办公网内网 DNS：同名解析 → NUC 内网 IP `192.168.3.22`，**同事在办公室直连，不绕公网**；
   - 同一域名、同一张正式证书，两边各用一份。
3. **边缘服务器 `/etc/hosts` 固定**：把 `patents.idrl.ac.cn` 指向 OpenVPN 隧道可达的 NUC 内网 IP——中间件转发时域名、TLS SNI、证书校验全部照常工作，不需要任何特殊代码。
4. **接入第二个系统**（复用此链路）：父域下新子域 → 新证书（现有为单域名证书，需新签或换通配符）→ 边缘 nginx 加 server 块与路径白名单 → relay 扩展白名单或新起实例 → VPN 账号 ACL 放行对应内网目标 → 目标系统签发 API 令牌。

## 三、钉钉侧配置（自建应用审批模板）

前置：钉钉专业版及以上（支持审批流连接器 / HTTP 请求节点）。

审批模板 → 流程设计 → 审批结束后添加「连接器」节点：

| 配置项 | 值 |
|---|---|
| 请求方式 | `POST` |
| URL | `https://<公网域名>/api/<目标接口>` |
| 请求头 | `X-API-Token: <边缘令牌>`、`Content-Type: application/json` |
| 触发时机 | 审批**通过**（节点条件设为审批结果 = 同意） |
| 请求体 | **`external_id` 必须绑「审批实例 ID」**（幂等键，重推自动去重），其余字段用「插入变量」绑表单控件 |

审批撤回/作废场景：再加一个 HTTP 节点调删除接口（`external_id` 同样绑审批实例 ID，放请求体）。

**HTTP 节点三个平台级坑**（跨项目通用，本项目实测踩过）：

1. **URL 不支持变量插值**——URL 里的 `${变量}` 会被原样发送；动态参数一律放请求体（本项目删除接口因此做成 POST 变体 `external-delete`，ID 走 body）。
2. **连接流用创建时快照**——连接器动作/请求头改完后，仅重新发布动作不够，**必须重建连接流**（或重新创建并启用）才用新配置；这是"立即调试成功、真实触发还是旧地址"的原因。
3. **钉钉云端校验 HTTPS 证书**——自签证书（mkcert）不可用；公网入口 nginx 必须挂正式证书。

字段级配置、请求体模板与更多排障见项目仓库 `docs/dingtalk-connector.md`。

## 四、边缘中间件行为速查（patents-relay）

| 环节 | 行为 |
|---|---|
| 接收 | 仅 nginx 转来的回调路径（本项目为 5 条：upsert / external-delete / DELETE external/:id / GET external/:id / GET revoked）+ 本机 /healthz |
| 校验 | ①边缘令牌（失败 401，**不解析 body、不触达源站**）②方法+路径白名单（403）③仅接受 JSON（415）、限请求体大小 |
| 转发 | 同方法+同路径+同 body；`X-API-Token` **换成内部令牌**（边缘令牌不出 VPN）；带来源 IP；keep-alive 复用连接；超时 8s（须小于钉钉节点超时约 5s，实测后收紧） |
| 输出 | 源站响应**原样透传**（钉钉拿到真实成败，不假 200）；隧道断+写操作 → 503（`retryable:true`）并落盘队列；隧道断+只读 → 502 不排队（回放过期查询无意义） |
| 补偿 | 每 30s 探测源站；恢复后 FIFO 重放：2xx 删文件；删除重放遇 404=成功（已删过）；4xx 转死信并告警（重试无意义）；5xx 保持顺序重试、超限转死信（防旧数据晚于新数据落库） |
| 幂等 | 源站以 `external_id` 为唯一键，重复推送/重放不会产生重复数据 |
| 告警 | 隧道断开/恢复、队列重放完成、死信产生 → 钉钉群自定义机器人 webhook |

**双层令牌**：边缘令牌（钉钉连接器请求头里的值，中间件本地校验）与内部令牌（目标系统 `/tokens` 页签发的那枚）分离，各自独立轮换互不影响。切换期可用"透传模式"（两者配同值）做到钉钉侧零改动，稳定后再拆开。

## 五、验证与排障

**不改线上 DNS 就能验证新边缘**（切换前必做）：

```bash
curl --resolve <域名>:443:<腾讯云IP> https://<域名>/api/<写入接口> \
  -H "X-API-Token: <边缘令牌>" -H "Content-Type: application/json" \
  -d '{"external_id":"manual-test-001", ...最小字段}'
```

| 现象 | 排查 |
|---|---|
| 连接器报 TLS/证书错误 | 边缘 nginx 证书无效/过期；先确认公网解析确实指向腾讯云 |
| 401 | 边缘令牌不匹配（连接器请求头 vs 中间件 `EDGE_TOKENS`） |
| 403 路径或方法不允许 | 新路径没进白名单——nginx location 与 relay `ROUTES` **两处都要加** |
| 502 | 隧道断且是只读请求：`curl 127.0.0.1:4330/healthz` 看 `tunnel.up`；查 `journalctl -u openvpn-client@office` |
| 503 `retryable:true` | 隧道断且写请求已排队：恢复后自动重放；积压看 `spool/pending/` |
| 推送成功但列表没变 | 被幂等去重了：先 `GET /api/patents/external/<id>` 查 |
| 改钉钉配置不生效 | 连接流快照——必须**重建连接流**（见三节坑 2） |
| DNS 方向不对 | 公网 `nslookup <域名>` 应出腾讯云 IP；办公网内应出 NUC IP（拆分解析） |

**鉴权模型说明**：本场景用**静态 API 令牌请求头**（目标系统自签发、自校验），不走 01 篇的连接器 OAuth2.0 五步鉴权——那是给"调钉钉侧接口/读 AI 表格"用的；回调自有系统时连接器只是个 HTTP 客户端，不需要 access_token。
