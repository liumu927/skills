# S0 全景与决策

先把"整条链路长什么样、谁负责谁、为什么这么选"定死，再进具体段。这一段是所有段的公共上下文。

## 一、两条数据流向

审批这件事本质上是**两个方向**的数据流动，混在一起谈是绝大多数误配的来源：

```
方向①（读到表单）：多维表 ──连接器──▶ 审批表单控件 / 流程审批人
   · 表单加载或控件变化时"拉一次"
   · 只读、同步、必须在表单里能用（下拉选项 / 回显文本 / 派单）
   · 详见 02

方向②（写出到系统）：审批表单 ──连接器 HTTP 节点 / 连接流──▶ 边界中间件 ──▶ 自有系统
   · 审批事件发生时"推出去"
   · 异步、要幂等、要能重放（审批会重试、人工会重推）
   · 详见 03 / 04 / 05 / 06
```

两条方向**可以共用同一个自建连接器**，但绑定点不同（表单绑定 vs 流程节点），互不影响。一个常见误解是"一个连接器只能发一个请求"——限制的是**每个绑定点**，不是连接器。

## 三、三套鉴权（最常混的地方）

| 鉴权 | 谁发凭据 | 谁校验 | 用在哪 | 别用在哪 |
|---|---|---|---|---|
| **企业内部应用**（Client ID/Secret → accessToken） | 钉钉开放平台 | 钉钉 | 调钉钉开放 API（多维表、通讯录）、连接器 OAuth2.0 的底层 | **不要**用在"回调自有系统"上，那边不经过钉钉 |
| **连接器 OAuth2.0**（五步向导，平台自动换/刷 token） | 连接平台 | 目标 API 提供方 | 连接器要调**需要 access_token 的 API**时 | 目标系统只认静态令牌时，不需要它 |
| **静态 API 令牌**（`X-API-Token` 请求头） | 自有系统自己签发 | 自有系统/中间件 | 审批 HTTP 节点 → 中间件、拉取接口、良构的内部调用 | 不要与 OAuth2.0 混配在同一个连接器上 |
| **用户登录态**（userAccessToken / 自签 JWT） | 钉钉（换 token）+ 自有系统（签发） | 自有系统 | 扫码登录、免登 | 与上面三者完全不同的东西，见 07 |

一句话：**调钉钉的东西要应用 token；钉钉调你的东西用你自己的令牌；人是另一套。**

## 四、边界形态选型（ADR-1）

| 方案 | 决策 | 理由 |
|---|---|---|
| frp / 裸端口映射 | **否决** | 等于把内网端口发布到公网，任何客户端可直达；无鉴权、无白名单、无审计 |
| 透明转发 + OpenVPN（形态 A） | **存量可用，不再新增** | 打通快、钉钉侧零改；但 VPN 常连=内网长期开一条通路，且无状态无法对账 |
| 落盘 store-and-forward + 内网拉取（形态 B） | **新项目默认** | 接住与处理解耦、可重放、可对账、甩掉 VPN 数据面 |
| 只放行回调路径 + 其余 404 | **保留**（两种形态都要） | 公网入口最小化，与形态无关 |

详见 05、06、11。**存量已跑通的形态 A 全部保留记录**，作为回退路径与迁移对照，不删除。

## 五、幂等键（ADR-2）

`external_id` = **审批实例 ID**，全链路唯一：

- 钉钉 HTTP 节点请求体里必须显式绑定"审批实例 ID"，不要自己拼时间戳/自增。
- 中间件按它 upsert；自有系统按它 upsert；重放、重推、断链补偿全部靠它收敛。
- 撤回/作废用**同一实例 ID** 调删除接口，才能删除"同一条"数据。

## 六、风险登记（现状 → 目标态如何缓解）

| # | 风险 | 现状影响 | 目标态缓解 |
|---|---|---|---|
| R1 | OpenVPN 常连 = 内网常驻入口 | 账号泄露即可进内网；ACL 配错无人发现 | 形态 B 取消数据面 VPN，内网只出站 |
| R2 | 边缘无状态、不落盘 | 钉钉重试/失败无记录，事后无法对账"到底收到没" | 落盘 + 状态机 + 对账接口 |
| R3 | 钉钉侧 5s 超时 vs 内网处理耗时 | 慢就报超时，但数据可能已处理 → 重复推送 | 落盘即 200，处理异步 |
| R4 | 多系统共用一套中间件无隔离 | 一个系统故障影响全部；令牌一换全停 | 一系统一队列/一路径/一令牌 |
| R5 | 静态令牌长期不轮换 | 泄露后无法快速止血 | 令牌版本化 + 双令牌并行期 |
| R6 | 域名职责冲突（回调域名 vs 登录域名） | 登录回调 404、或被迫拆 DNS 引出五断点 | 登录另开子域，不复用回调域名（见 07a §存量系统） |
| R7 | 明细逐条循环计量 | 大单审批费用高、跑满 100 条要分页 | 批量走自有系统接口（一条消息带全部明细） |

## 七、先问清楚的五个问题

配置前必须能回答，答不上就先别动手：

1. 数据最终落在哪？AI 表格 / 自有系统 / 两处都要
2. 触发时机：审批**通过**、审批**结束**、还是**撤回也要同步**
3. 每条数据的**唯一键**是什么（本方案：审批实例 ID）
4. 实时性要求：秒级 / 分钟级 / 一天内（决定拉取调度方式，见 06）
5. 谁承担失败：钉钉重试 / 中间件补偿 / 内网重放（三者只能有一个主责）
