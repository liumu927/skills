# 数据模型：ID、API、字段值形态

跨场景共享底座。配置前先确认"这个位置要的是哪套 ID、字段值该长什么样"，能避开大半报错。

## 三套 ID

| 标识 | 归属 | 典型用途 | 注意 |
|---|---|---|---|
| **userId** | 企业通讯录侧 | 审批节点负责人、联系人控件、官方连接器人员字段槽位 | 审批派单最终要它 |
| **unionId** | 开放平台/应用侧 | `records/list` 的 `operatorId`、多维表人员列存的值、自定义连接器直连 API 的人员列 | 不能直接当审批人 |
| **operatorId** | API 的"操作人"参数 | 读/写多维表时以谁的身份做权限校验 | 语义是**服务身份**，固定值即正确设计，不是当前表单用户 |

转换链路：

- unionId → userId：系统自带「通讯录」连接器 →「根据unionid获取用户userid」，免鉴权，不要自建。
- 反向需用对应通讯录动作，循环骨架照搬。
- 查某个人的 unionId/userId：开放平台「查询用户详情」接口，按人查一次。

`operatorId` 的常见误解：想把它做成"当前审批人"。审批表单+连接器架构没有挂载点拿当前用户（免登码需要 H5 调 JSAPI），固定一个管理员/服务账号的 unionId 才是正确做法。该账号离职/删号会导致整条链路失效，务必用长期不动的账号。

## AI 表格（多维表）API

| 操作 | 接口 |
|---|---|
| 列出数据表 | `GET /v1.0/notable/bases/{baseId}/sheets?operatorId=...` |
| 查记录 | `POST /v1.0/notable/bases/{baseId}/sheets/{sheetIdOrName}/records/list` |
| 新增记录 | `POST /v1.0/notable/bases/{baseId}/sheets/{sheetIdOrName}/records` |
| 更新记录 | `PUT /v1.0/notable/bases/{baseId}/sheets/{sheetIdOrName}/records` |

通用规则：

- `baseId` 从表链接/文档信息面板取；`sheetIdOrName` **优先用表 ID**（`GET /sheets` 返回的短 ID），避免中文表名 URL 编码问题。
- `maxResults` 上限 100；超过走 `nextCursor` 分页。
- 查记录筛选：`filter` 里 `combination` + `conditions`（顶层数组），子项 `{field, operator, value(array)}`；`field` 是表格列名，`operator` 用 `equal` 等。
- "条件"参数不能只有字段名没有操作符/值（报 `operator 'null' is invalid`）；不筛选就整个留空。
- 出参 `records[]` 每项形如 `{id, fields:{列名: 值}}`。

## 字段值形态

| 表格列类型 | 写入形态 | 备注 |
|---|---|---|
| 文本 | 字符串 | fields 的键 = 列头，一字不差 |
| 单选/下拉 | 直连 API 通常传 `{"label": "...", "value": "..."}` 或按接口要求；从审批取值时先 JSONPath 取 `.label` | 传整个对象常报格式错 |
| 人员 | 直连 API：`[{"unionId": "..."}]` 对象数组 | 裸字符串、`["unionId"]` 字符串数组都 ❌ |
| 人员（官方连接器槽位） | 用户 ID 字符串，由官方动作内部转换 | 与直连 API 不同 |
| 日期 | 建议存文本列，取 `LEFT(时间, 10)` | 见下方"假 Z" |
| 多选 | 按接口要求传数组 | 不要塞成字符串 |

## 时间字段的"假 Z"

连接器返回的时间形如 `2026-10-19T16:41Z`，这个 Z 是假的——实际是本地时间 16:41。日期列按 UTC 解析会 +8 小时，跨零点就变成第二天。

处理：`LEFT(时间字段, 10)` 取前 10 位存**文本列**；凡是这个连接器给的时间，一律按本地时间理解。

## 权限三道门

调用多维表报 403 时，按顺序查：

1. 应用权限点：是否开通 `Notable.Base.Read.All`（写操作对应写权限），修改后是否发版。
2. 文档访问权：目标多维表是否对应用/组织可见；个人文档必须共享。
3. 应用状态：是否已上线；Client Secret 是否被重置（重置后所有凭证失效，需重新授权）。

## 官方连接器 vs 自建 HTTP 连接器

| 场景 | 选择 |
|---|---|
| 只需新增/更新，官方动作槽位够用 | 官方 AI 表格连接器（选表自动生成字段槽位，人员填 userId 字符串） |
| 需要把字段值回填到审批表单 | **自建 HTTP 连接器**（官方不暴露字段值，只有记录 ID/游标） |
| 需要按条件精确查询记录 id | 自建 HTTP 连接器（官方列表动作不返回记录 id 集合） |
| 需要一次批量 upsert | 自建连接器直连自有服务，后端处理；直连 AI 表格 API 做不了 |
