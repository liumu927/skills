# AI 表格自动化：循环回写

适用：AI 表格某张数据表里每行存着人员标识 + unionId，需要批量把 unionId 换算成 userId 回写到同一行；或任何"取全表 → 逐行处理 → 按当前行 id 更新"的定时批处理。

前置：表内有人工可读的人员标识列、已填好的 unionId 列、用于回写的 userId 列；通讯录连接器 `unionId→userId` 可用（系统自带、免鉴权，不要自建）。

## 架构

```
节点1 定时触发
   ↓
节点2 获取数据表多行记录（AI表格）
   ↓ 入参 sheetIdOrName=数据表, baseId=..., pageSize=100
   ↓ 出参 records[]（本次 N 条）, nextCursor
节点3 循环执行（循环方式=按数组）
   ↓ 循环内容 = 节点2:结果.记录[*]      ← 必须是"整条记录"这一层
   └─ 节点4 获取数据表单行记录
        recordId ← 循环当前项.id
        出参 unionId / name / id
   └─ 节点5 根据unionid获取用户userId（通讯录）
        入参 unionId ← 节点4.unionId
   └─ 节点6 更新人员userId
        更新目标 ← 循环当前项.id（推荐）
        写入值   ← 节点5.userid
```

一句话：**循环内容要选到"整条记录"，循环体内一律引用"循环当前项"，绝不引用上游节点的固定下标。**

如果节点2 的 records 已经带 unionId 字段，节点4 可以整个删掉，节点5 直接取"循环当前项 → 字段 → unionId"，少一次读取调用和循环计量。

## 配置步骤

### 阶段 A：取数节点

1. 节点2 填 baseId、表名（建议用表 ID），pageSize=100，先跑一次。
2. 核对出参 `records` 条数与表内实际一致（异步/分页问题最早在这里暴露）。

### 阶段 B：循环节点（核心）

1. 数据类型 = **数组**。
2. 循环内容：选「节点2 → 结果 → 记录」，下标位保持 `[*]`，**选到 `记录[*]` 这一层为止，不要继续往下点 `.字段`**。
3. 最大循环数据条数按实际填（界面默认 100、最多 500，以版本为准）。
4. 跑一次，在循环节点入参里确认循环项形如 `{id: "...", 字段: {...}}`——**有 id 才算选对**；若入参是 `{邮箱, 手机号, 人员}` 这种纯字段值、没有 id，说明还停在 `.字段` 层。

### 阶段 C：循环体内节点

1. 节点4 recordId ← **循环当前项.id**（不要选"节点2 的第一条"）。
2. 节点5 入参 unionId ← 节点4 的 unionId 出参。
3. 节点6 更新目标 ← **循环当前项.id**；写入值 ← 节点5 的 userid。
4. 保存，完整跑一次。

## 验证清单

- [ ] 循环节点出参 `index` 跑到"记录数-1"（18 条 → index 17），说明跑满
- [ ] 节点4 执行详情切换「循环执行次数」，每次 recordId 都不同（恒定即踩坑 3）
- [ ] 回表核对：每条 userId 都对上人，不重复、不空缺

## 踩坑

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| 1 | 循环跑了十几遍、节点全绿无报错，但只有第一条被写入 | 循环内容选到了 `记录[*].字段`，循环项不含记录 id，循环体内只能引用节点2 的第一条 | 循环内容上移一层选 `记录[*]`；记录引用改"循环当前项.id"。**招牌坑** |
| 2 | 循环只跑一次 | 下标选成了具体值 `[1]` 而非 `[*]` | 下标位保持 `[*]` |
| 3 | 每次循环都处理第一条 | 循环体内引用固定下标，如 `记录[1].id` | 改引用循环当前项；切换循环次数验证 |
| 4 | 节点4 查不到记录时，节点6 更新失败 | 节点6 沿用了节点4 的出参 id，形成隐式依赖 | 更新目标直接引用循环当前项.id |
| 5 | 每条多一次"获取单行"，循环计量翻倍 | unionId 本来就在节点2 返回的字段里 | 循环内容选 `记录[*]` 后直接取循环当前项字段，删掉节点4 |
| 6 | 超过 100 条后后面的记录不动 | 节点2 pageSize=100 只取第一页（有 nextCursor）；循环节点也有上限 | 分页取值，或加筛选条件分批跑 |
| 7 | [观察项] 出参 items 比 records 少 1 | 未定性 | 回表核对是否漏记录；全量正确则忽略 |

## 维护

- 记录数增长：处理分页/分批。
- 只想补空缺：给节点2 加筛选条件（只取 userId 为空的行），避免每次全表重跑。
- 人员离职/换 unionId：表内更新后重跑；查无此人的行会在循环里报错，按行定位。
- 发布：自动化流程改完即生效，没有"连接器发布→模板发布"那套链路（与审批侧不同）。

## 复用

- 换表/换列：改节点2 的 baseId+表名、节点4 的列引用、节点6 的写入列，循环骨架不动。
- 换翻译方向（unionId→userId 换成 userId→unionId）：只换通讯录侧动作。
- 一台流程翻译多列：循环体内并排加节点。
- 通用模板：一切"逐行批处理"都套三步——**取全表 → 循环整条记录 → 按当前项 id 更新**。
