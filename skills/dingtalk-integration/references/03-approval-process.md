# 审批流程节点审批人路由

适用：审批流程的某个节点，审批人要按表单数据动态决定——典型是"选了项目，第一个节点自动派给该项目的负责人"。

前置：`02-approval-form.md` 已把负责人姓名和 unionId 回显到表单文本控件。

## 两段式架构

```
表单层（一次请求）
  选定项目 → 连接器按项目名查表 → 回显负责人姓名 + 负责人unionId 到两个文本控件
       ↓ unionId 落到控件里（参数桥）
流程层（流程运行时再发一次请求）
  节点负责人来源=连接器 → 系统自带「通讯录」连接器
       ↓ 动作「根据unionid获取用户userid」
       ↓ 入参 unionId ← 表单控件「负责人unionId(回显)」
       ↓ 出参 userid → 该节点审批人
```

为什么必须两段：

- 审批节点按 **userId** 定位人，多维表里存的是 **unionId**。
- 表单级连接器不能链式调用，拿到 unionId 后没法在表单里再调一次换 userId。
- 流程级节点只能引用表单控件值或固定值，拿不到表单级连接器的运行时出参。

所以：unionId 必须落到文本控件，这是第二次调用的**参数桥**，不只给人看。

## 配置步骤

### 阶段 A：表单层回显

按 `02-approval-form.md` 用途二配置，产出两个文本控件：
- `项目负责人(回显)` ← `records[0].fields.项目负责人`
- `负责人unionId(回显)` ← `records[0].fields.负责人unionId`

### 阶段 B：流程设计

1. OA 审批后台 → 编辑审批模板 → 流程设计 → 找到目标审批节点 → 编辑审批人/负责人。
2. 负责人来源选"**连接器**" → 连接器选**系统自带「通讯录」**（平台托管，免鉴权，不要自建）。
3. 动作选「**根据unionid获取用户userid**」；入参 unionId = 引用表单控件 `负责人unionId(回显)`。
4. 出参 userid 自动成为节点负责人。
5. 字段权限：两个回显控件对发起人设为**只读**。
6. 发布模板。

## ID 体系提醒

| 标识 | 归属 | 谁在用 |
|---|---|---|
| userId | 企业通讯录侧 | 审批节点负责人、联系人控件 |
| unionId | 开放平台/应用侧 | 多数开放 API（`records/list` 的 operatorId）、多维表里存的值 |

「根据unionid获取用户userid」就是官方提供的翻译器，系统自带、免鉴权，别自建。

## 验证清单

- [ ] 选项目 A → 两个文本控件回显 A 的负责人姓名和 unionId；改选 B → 跟随变化
- [ ] 提交 → 节点待办落在 A 的负责人名下（管理员后台或该人客户端确认）
- [ ] 换项目 B 再发起 → 节点跟随到 B 的负责人
- [ ] 负向测试（可选）：临时清空某条记录的负责人列，观察提交时报错，测完恢复

## 踩坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 想用联系人控件携带负责人，出参塞不进去 | 联系人控件按 userId 定位，表里是 unionId；表单级不能链式 | 改两个文本控件回显，userId 转换下沉到流程节点 |
| 直接给节点 unionId，节点取不到人 | 节点要 userId | 走通讯录连接器转换 |
| 节点报"未找到审批人" | unionId 查不到 userid：离职、非本企业成员、表里填错 | 用"查询用户详情"逐个核对；离职交接加"同步更新表内负责人"一步 |
| 发起人手改 unionId 控件，审批连到别人 | 文本控件默认可编辑 | 字段权限设为只读 |
| 审批人派错人 | 项目名重复，取第一条匹配记录 | 名称唯一性治理；确需同名时加第二字段联合过滤 |
| 选了项目但控件空白 | 表里无匹配记录，或负责人列本身为空 | 核对数据；负责人姓名+unionId 两列必填 |
| 提交后节点无负责人，流程不动 | 回显是异步的，极速"选完就交"存在竞态 | 操作上让发起人确认回显已更新再提交 |

## 复用

- 换条件维度：改动作条件字段 + 出参 json + 表单映射三处。
- 一个项目多个人审批：每人一条"unionId 控件 + 通讯录连接器节点"组合。
- 复制到其他模板：三段式整体照搬，连接器无需重建。
- 平台若未来支持联系人控件直接接收 userid 或表单级链式请求，可简化为一层；现阶段按两段式实施。
